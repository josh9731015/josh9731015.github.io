接手並強化 ｜ Python、SQL Server

報價上傳工具

成果：上傳失敗的檔案會列出原因，不再被漏掉；執行時間從約 3 小時縮短到 1.5 小時

每月價格資料流：報價上傳工具→SQL Server 價格資料庫→報價驗證工具→Owner 審核

痛點：每月 100 多份 ODM 報價檔（約 1 萬筆報價）要上傳；範本填錯的檔案上傳失敗，卻看不出是哪些，到核對價格時才發現缺價格。

錯誤清單 （示意）

檔案位置問題
ODM B標題列欄位標題不符規定格式
ODM C第 7 列Effective date 填「ASAP」，不是日期或規定代碼

橘字＝錯誤原因。日期規則原本就有，現在沒通過的檔案也一起寫進清單

解法：ETL 流程，加上資料品質檢查與錯誤紀錄

擷取Extract
讀入 100 多份報價檔讀不到 ODM 名稱時改從檔名判斷；只開一次 Excel、只讀需要的欄位，改完比對產出與原版一致才上線
轉換Transform
資料品質檢查標題格式、必要 sheet 是否存在，加上原有的日期規則
載入Load
寫入 SQL Server原有通過檢查的報價上傳到價格資料庫
錯誤紀錄Error log
錯誤清單沒通過的檔案寫出位置與原因，Owner 修正後重新上傳

接手維護 ｜ Python、SQL Server

報價驗證工具

成果：修正 3 個讓價格比對出錯的問題：價差計算正確、機種比對更準確、重複標題會被標出

每月價格資料流：報價上傳工具→SQL Server 價格資料庫→報價驗證工具→Owner 審核

痛點：Owner 每月用這個工具確認 ODM 報價裡每個料號的價格是否跟內部價格一致；但工具的公式和規則跟不上 ODM 範本與機種命名的變化，比對會出錯。

價差＝ODM 價格 − 內部價格；橘底＝有價差，需要 Owner 確認

解法：依最新規則，修改對應欄位的公式與比對規則

價差公式問題：每家 ODM 的價格欄位位置不同，價差會算錯改法：價差欄位的公式改成符合最新的範本規則
機種名稱比對問題：新的衍生機種名稱開頭跟原機種相同，會抓錯價格改法：更新比對規則，提高比對準確度
重複標題檢查問題：ODM 範本有時誤打重複標題改法：新增檢查，標出來請 Owner 修正

接手並強化 ｜ Power BI、Power Query

成本節省報表

成果：逐月區分今年新增與前一年延續的節省，今年的成果不被高估

痛點：一筆節省會延續 12 個月，可能跨兩個財年。原本依開始日期整筆分類，跨到下一個財年的月份也被算成今年新增的；節省明細也對不到專案 ID。

一筆節省拆成 12 個月逐月判斷 （簡化示意：2025 年 6 月開始，財年從 11 月起算；少數類別另有規則）

月份25-0625-0725-0825-0925-1025-1125-1226-0126-0226-0326-0426-05 所屬財年FY25FY25FY25FY25FY25FY26FY26FY26FY26FY26FY26FY26 分類新增新增新增新增新增延續延續延續延續延續延續延續

新增＝跟開始月份同一個財年 延續＝跨到下一個財年

解法：Power Query ETL 流程

擷取 Extract讀入來源資料原有節省明細、專案清單與 ID 對照表
→
轉換 Transform逐月標記比對每個月所屬財年與開始的財年
→
轉換 Transform對上專案 ID共有欄位（含新增／延續）串成比對欄位再 left join，才能依專案呈現
→
載入 Load → 呈現Bookmark 切換視角在 Power BI 用 Bookmark 選基準年，看某財年的新增與延續
